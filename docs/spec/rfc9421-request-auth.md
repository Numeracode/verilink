# RFC 9421 Request Authentication — VeriLink Implementation Spec

Reference: RFC 9421 HTTP Message Signatures. Go stdlib only. No new dependencies.

## 1. Algorithm

- **Ed25519** (`ed25519.Sign` / `ed25519.Verify`) — no RSA/ECDSA.
- Private key: 64-byte Go `ed25519.PrivateKey` (seed || public).
- Public key: 32-byte `ed25519.PublicKey`.
- No key wrapping; transport is out-of-band per deployment.

## 2. Signature Components (covered)

`"@method"`, `"@target-uri"`, `"@created"`, `"@expires"`, `"content-digest"` (when body non-empty).

`"@authority"` is omitted — subsumed by `"@target-uri"` which includes scheme, host, path, and query.

## 3. Canonicalization

One component per header name, sorted alphabetically, each on its own line, no blank lines.

```
"@method": POST\n"@target-uri": https://example.com/api/v1/resource\n"@created": 1234567890\n"@expires": 1234567950
```

`content-digest` (if present) is appended last.

No trailing newline after the final component.

## 4. content-digest

```
content-digest: sha-256=:base64url(sha256(body)):
```

Computed with `crypto/sha256.Sum256(body)`, encoded with `encoding/base64.RawURLEncoding` (no padding).

## 5. Timing Fields

- **`created`**: Unix timestamp (seconds).
- **`expires`**: Unix timestamp; `created` + 300s (5 min max).
- **Clock skew**: ±30s acceptance window during verification.
- **Replay window**: nonces valid only within the `@created`..`@expires` interval.

In practice the verifier rejects requests where `now < created-30` or `now > expires+30`.

## 6. Nonces

- 128-bit random hex string generated by the signer.
- Cache key: `keyid + ":" + nonce` (scoped per signer).
- TTL: 5 minutes.
- Background sweeper removes expired entries every `ttl/2`.
- `CheckAndConsume` uses a write lock; first caller wins.

## 7. Key Identification

**Key ID format:** `vrl:agent:<did>:<label>`

Example: `vrl:agent:did:web:example.com:agent1:signing-key`

**Key hash (key_hash):** `SHA-256(raw 32-byte Ed25519 public key)` encoded as `base64url` (no padding, no hex).

Used for registry lookups and dedup without storing the raw key.

## 8. Agent Registry

JSON file (`[]AgentEntry`) loaded at startup via `--agent-keys-path`.

```json
[
  {
    "did": "did:web:example.com:agent1",
    "key_label": "signing-key",
    "public_key": "<base64url 32-byte Ed25519>",
    "allowed_uris": ["https://api.example.com/*"]
  }
]
```

Registry supports:
- `Register` / `Lookup` by keyid
- `GetPublicKey` — decodes base64url, validates length

No rotation mechanism defined yet.

## 9. Three-Way Outcome Model

| Incoming request | `require-signatures` | Result |
|---|---|---|
| Signed + valid sig | false | Allow → proxy (auth bypassed by sig, trust store still consulted for score) |
| Unsigned | false | Passthrough → proxy, `X-Verilink-Auth-Status: unsigned-passthrough` |
| Unsigned | true | 401 Reject, `X-Verilink-Auth-Status: unsigned-rejected` |
| Signed + invalid | either | 401 Invalid signature, `X-Verilink-Auth-Status: invalid-signature` |
| Signed + unknown key | either | 401 Invalid signature, `X-Verilink-Auth-Status: invalid-signature` |

## 10. CLI Flags (edge-verifier)

| Flag | Default | Purpose |
|---|---|---|
| `--external-base-url` | "" | Override scheme/host for `@target-uri` reconstruction (e.g. behind a load balancer that sets `X-Forwarded-*`) |
| `--agent-keys-path` | "" | Path to JSON agent registry |
| `--require-signatures` | false | Reject unsigned requests |
